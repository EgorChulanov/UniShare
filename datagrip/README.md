# Управление UniShare через DataGrip

Откройте папку `/Users/egorchulanov/Desktop/UniShare/datagrip` как проект
DataGrip. В проекте настроены два подключения:

- `UniShare — удалённая база` — настоящие данные приложения в Supabase;
- `UniShare — локальная база` — тестовая база на этом Mac.

## Подключение к удалённой базе

Если DataGrip снова попросит параметры, откройте Supabase Dashboard, нажмите
`Connect` и выберите `Session pooler`. Укажите:

- Host: `aws-1-us-east-1.pooler.supabase.com`;
- Port: `5432`;
- Database: `postgres`;
- User: `postgres.kwonpzkzthprilrhncik`;
- SSL mode: `require`;
- Schemas: `public`, `auth`, `storage`;
- Password: пароль базы данных из Supabase, хранить только в Password Safe.

Publishable key не является паролем PostgreSQL. Пароль базы, service-role key и
полную строку подключения нельзя сохранять в Git или вставлять в приложение.

Начните с файла `00_health.sql`: он только читает данные и проверяет подключение.

## Как удалённо добавить историю с фотографией

DataGrip управляет строкой истории в PostgreSQL, но не может напрямую загрузить
файл с Mac в Supabase Storage. Поэтому операция состоит из двух коротких этапов.

### 1. Загрузить фотографию

1. Откройте Supabase Dashboard проекта UniShare.
2. Слева выберите `Storage`.
3. Откройте хранилище `story-media`.
4. Для порядка создайте папку, например `stories/2026-08`.
5. Нажмите `Upload file` и выберите JPG, PNG или WebP размером до 15 МБ.
6. Используйте уникальное имя, например `airshare-2026-08-23.webp`.
7. Откройте загруженный файл и нажмите `Copy URL` / `Get URL`.

Полученная ссылка должна начинаться так:

```text
https://kwonpzkzthprilrhncik.supabase.co/storage/v1/object/public/story-media/
```

### 2. Создать историю в DataGrip

1. Откройте `21_stories_admin.sql`.
2. Убедитесь, что справа сверху выбрано подключение
   `UniShare — удалённая база`.
3. При желании сначала выполните блок `ПРОВЕРИТЬ ССЫЛКУ НА ФОТО`.
4. Снимите комментарий только с блока `СОЗДАТЬ НОВУЮ ИСТОРИЮ`.
5. Выделите этот блок и нажмите Run. Не запускайте весь файл целиком.
6. Вставьте данные истории; в `IMAGE_URL` вставьте URL из Storage.
7. После создания снова запустите первый безопасный запрос файла.

История появится в приложении, если `is_active = true`, время `published_at`
уже наступило, а `expires_at` пустое или находится в будущем.

Чтобы изменить, скрыть или повторно опубликовать историю, используйте подписанные
блоки в конце `21_stories_admin.sql`. Для обычного скрытия выбирайте архивирование:
оно сохраняет статистику просмотров.

## Локальная тестовая база

Подключение `UniShare — локальная база` использует `127.0.0.1:55432`.

```bash
cd /Users/egorchulanov/Desktop/UniShare
make backend-start
```

Пароль локальной базы: `postgres`. Он нужен только для локальной разработки.
Локальные данные отделены от production и сбрасываются командой:

```bash
make backend-reset
```

## Назначение файлов

- `00_health.sql` — проверить подключение, RLS и Storage;
- `10_users_readonly.sql` — посмотреть пользователей;
- `20_stories_readonly.sql` — посмотреть истории и просмотры;
- `21_stories_admin.sql` — создать, изменить, скрыть или удалить историю;
- `22_аватары_админ.sql` — управлять каталогом готовых аватаров;
- `30_moderation_readonly.sql` — посмотреть жалобы;
- `40_admin_overview.sql` — общая административная панель;
- `50_game_catalog_admin.sql` — проверить или заменить RAWG API key и управлять играми.
- `51_установить_ключ_rawg.sql` — одним запуском установить или заменить RAWG key.
